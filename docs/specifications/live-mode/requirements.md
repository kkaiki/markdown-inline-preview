# Live モード 要件定義

**目的**: VS Code 上で **Obsidian の Live Preview と同じ操作感**の Markdown 編集体験を提供する
新しいモードを追加する。

**前提**: 実測仕様は [obsidian-observed-spec.md](obsidian-observed-spec.md) が正。
本書はそこから「我々が何を満たすか」を切り出したもの。実装方針は
[architecture.md](architecture.md)。

**優先度の記法**: `MUST` = これが無いと Live モード を名乗れない / `SHOULD` = 同じ操作感のために
必要だが初期リリースからは外せる / `WON'T` = 意図的にやらない。

---

## 0. スコープ

### 0.1 やること

- `.md` / `.markdown` を対象にした**3つ目のモード**として Live モード を追加する。
- 既存の Raw モード・Preview モードは**一切変更しない**。
  Live モードは独立した viewType / コマンド / 設定名前空間を持つ。
- Obsidian 固有の記法のうち、**Markdown ファイルとして意味が閉じているもの**を対象にする。

### 0.2 やらないこと（WON'T）

| 項目 | 理由 |
|---|---|
| vault 概念・グラフビュー・バックリンク | VS Code のワークスペースと二重管理になる |
| `[[wikilink]]` の解決とリンク先ジャンプ | 初期スコープ外。表示（`[[ ]]` を隠す）だけ対応する → §2.2 |
| Obsidian コミュニティプラグイン互換 | 別物 |
| frontmatter のプロパティパネル UI | §2.9 で「生表示のまま」に倒す |
| Obsidian の Reading view 相当 | 既存の VS Code 標準プレビューで足りる |
| Obsidian と同一のテーマ・配色 | VS Code のテーマ色に従う |

---

## 1. 基本原則（すべての要件の前提）

### R1.1 `MUST` ドキュメントは生の Markdown テキストそのもの

エディタが保持する文書は、ファイルの中身と1文字も違わない文字列でなければならない。
Markdown → 別モデル → Markdown の往復変換を**してはならない**。

**受け入れ基準**
- 任意のファイルを Live モード で開き、1文字も編集せずに閉じたとき、
  ファイルの内容が**バイト単位で不変**であること。
- 任意の編集操作の後、エディタの文字列が VS Code の `TextDocument` と完全一致すること。

### R1.2 `MUST` カーソルオフセットは常にソースと 1:1

記法が収縮表示されていても、カーソル位置・選択範囲はソース文字列のオフセットで表現され、
装飾によってズレてはならない。

**受け入れ基準**
- `- 項目1` の行で `End` を押すと、カーソルは C5（`- ` を含む実長）に来ること。
- 収縮中の行で `→` を押すと、隠れている記法文字の上を**1文字ずつ**通過すること
  （まとめてスキップしないこと）。

### R1.3 `MUST` 展開スコープは4種類（トークン / 行 / ブロック / 常時変換）

要素ごとに [obsidian-observed-spec.md §1 原則2](obsidian-observed-spec.md) のスコープを実装する。

**トークンスコープの判定式**: `token.from <= cursor <= token.to`（**両端を含む**）。
`token.to` はトークン最終文字の次のオフセット。

**受け入れ基準**
- `これは **太字bold** と *斜体italic* です。` で、カーソルを 0 から行末まで動かしたとき、
  `**太字bold**` が展開されるのは **オフセット 4〜14 のみ**であること。
- 同じ行の `*斜体italic*` はそのとき収縮したままであること。

### R1.4 `MUST` フォーカスを失ったら全て収縮する

エディタが blur したら、展開中の要素をすべて収縮させる。カーソル・選択範囲は保持する。

### R1.5 `MUST` 選択範囲が触れた要素はすべて展開する

選択が複数行・複数トークンにまたがる場合、またいだ要素をすべて展開する。

### R1.6 `MUST` クリック位置は意味的に正しいソースオフセットへ着地する

収縮表示された文字をクリックしたとき、展開でテキストが横にずれても、
カーソルは**クリックした文字のソース上の位置**に来なければならない。

**受け入れ基準**
- 収縮中の `これは **太字bold** です。` の `太字bold` の中央（`字` と `b` の境目）を
  クリックすると、カーソルは C8 に来ること。

## 2. 要素別要件

各要素の「収縮時の見た目」「展開スコープ」は実測仕様のマトリクスに従う。
ここでは実装上の判断が要る点だけを書く。

### 2.1 見出し `MUST`

| 項目 | 要件 |
|---|---|
| 対象 | `# ` 〜 `###### `（H1〜H6） |
| 収縮時 | `#` とその後ろの空白を非表示。**フォントサイズ・太さは見出しのまま維持** |
| 展開スコープ | **行** |
| 装飾 | 既存 Raw モードの `headingColorScheme` 設定を流用する `SHOULD` |

**受け入れ基準**: 見出し行のどのオフセットにカーソルがあっても `# ` が表示され、
かつ**行の高さが変わらない**こと（横方向のずれのみ）。

### 2.2 インライン記法 `MUST`

| 記法 | 収縮時 | 優先度 |
|---|---|---|
| `**太字**` / `__太字__` | マーカー非表示・太字 | `MUST` |
| `*斜体*` / `_斜体_` | マーカー非表示・斜体 | `MUST` |
| `***太字斜体***` | 両方適用 | `MUST` |
| `~~取り消し線~~` | マーカー非表示・打ち消し | `MUST` |
| `` `コード` `` | マーカー非表示・等幅 + 背景 | `MUST` |
| `==ハイライト==` | マーカー非表示・背景色 | `SHOULD`（Obsidian 独自記法） |
| `[表示](URL)` | `表示` のみ・リンク色 | `MUST` |
| `[[内部リンク]]` | `内部リンク` のみ・リンク色（**ジャンプは非対応**） | `SHOULD` |
| `![alt](URL)` | 画像ウィジェット | `SHOULD` |
| `$数式$` | KaTeX ウィジェット | `SHOULD` |

**すべて展開スコープは「トークン」。**

**常に生表示のままにするもの（`MUST`）**: 生 URL、`#タグ`、`[^1]`（脚注参照）、`%%コメント%%`。

**行スコープにするもの（`SHOULD`）**: エスケープ `\*`、脚注定義 `[^1]: 本文`。

### 2.3 リスト `MUST`

| 項目 | 要件 |
|---|---|
| 箇条書き `- ` `* ` `+ ` | マーカー文字を**透明化して残す**（`color: transparent` 相当）。`•` を擬似要素で描画 |
| 番号リスト `1. ` | 数字はそのまま表示 |
| 展開スコープ | **常時変換**（カーソルが来ても生の `-` を見せない） |
| ネスト | インデント量に応じて視覚的に段付け。2スペース / 4スペース / タブすべて認識 |

**受け入れ基準**: `- 項目1` の行にカーソルを置いても表示は `• 項目1` のままで、
かつ `Home` `Home` で C2 → C0 と移動できること（＝ `-` の文字が実在すること）。

### 2.4 チェックボックス `MUST`

| 項目 | 要件 |
|---|---|
| 対象 | `- [ ] ` / `- [x] ` / `- [X] ` |
| 収縮時 | チェックボックス UI に置換 |
| 展開スコープ | **トークン** `[行頭, 行頭+5]` |
| クリック | レンダリング済みチェックボックスのクリックでソースの `[ ]`↔`[x]` を書き換える |
| チェック済みの本文 | 打ち消し線スタイル `SHOULD`（既存 `hideStrikethroughOnEdit` 相当の設定を流用） |

### 2.5 引用 `MUST`

- `>` を**透明化して残す**（リストと同じ方式）。左に縦罫線を描画。
- 展開スコープは**常時変換**。
- 多重引用 `>> ` はネスト段数ぶんの罫線を描画する `SHOULD`。

### 2.6 コードフェンス `MUST`

| 項目 | 要件 |
|---|---|
| 収縮時 | 開始フェンスは**言語ラベル**表示、終了フェンスは空表示。本文は常に生テキスト |
| 展開スコープ | **ブロック**（本文行にカーソルがあれば両フェンスとも展開） |
| ハイライト | 言語に応じたシンタックスハイライト `MUST` |
| `Tab` | **タブ文字を挿入**（インデント操作にしない） |
| 閉じフェンス自動補完 | ` ```lang ` + `Enter` で閉じフェンスを自動挿入 `SHOULD` |

### 2.7 表 `MUST`

| 項目 | 要件 |
|---|---|
| 収縮時 | 実 `<table>` としてレンダリング |
| 展開スコープ | **常時変換**（パイプ記法の生表示に戻さない） |
| 編集 | セルを `contenteditable` にして**セルの中で直接編集**する。入力は該当セルのソース範囲だけを置換する差分になる |
| セル内のキー | `Tab` / `Shift+Tab` で隣のセルへ移動。`Enter` は改行を入れない（表が壊れるため）。`Escape` でエディタ本体へ戻る |
| 複数セル選択 | セルは個別の `contenteditable` なのでブラウザの選択はセルをまたげない。**ドラッグ（と Shift+クリック）で矩形選択**し、選択セルをハイライトする。`⌘C` は列をタブ・行を改行で区切って書き出す（表計算ソフトへ貼れる）。`Escape` で解除 |
| 入力の制限 | セルに `\|` と改行は入れられない（入力しても取り除く） |
| ソース整形 | 列幅を揃えるパディングを**自動で行うかは設定にする**（既定 OFF）`SHOULD` |

#### 2.7.1 実装メモ（Phase 4b で Obsidian と同じ挙動に到達）

Phase 4 ではブロックスコープ（カーソルを入れると生のパイプ記法）で暫定実装していたが、
Phase 4b で **Obsidian と同じ「畳んだまま、セルの中で編集」** に揃えた。

セルの範囲は `src/live/shared/tableCells.ts` がソースの実オフセットで返す。ここが
1文字でもズレると入力が隣のセルへ入りドキュメントが壊れるため、純関数として
単体テストで固定してある。

**受け入れ基準**: 先頭セル・2番目のセル・本文行のセルそれぞれに入力したとき、
ソースの該当セルだけが変わること。連続入力・別セルへの移動後も範囲がズレないこと。

> Obsidian は表に入ると無条件でソースを整形する。これは差分ノイズになるため、
> 既存の `markdownInline.advanced.autoFormatTables`（既定 false）と同じ思想で
> 既定 OFF にする。

### 2.8 ブロックウィジェット `SHOULD`

| 要素 | 収縮時 | 展開スコープ |
|---|---|---|
| 水平線 `---` `***` `___` | 罫線ウィジェット | **行** |
| 数式ブロック `$$ … $$` | **ソースを常に表示**し、その下に KaTeX の描画結果を併記 | **常時変換**（畳まない） |
| コールアウト `> [!note]` | コールアウトボックス | **ブロック** |

`↓` で上から入ったとき、ブロックが展開されて**先頭ソース行の C0** に着地すること。

### 2.8.1 数式ブロックは「ソース＋下にプレビュー」（Obsidian からの逸脱）

Obsidian はカーソルが外にあるとき数式ブロックを描画結果だけに畳むが、
**我々は畳まない**。ソースは常に見せて編集できる状態を保ち、その下に描画結果を
併記する（ユーザー指示 2026-08-05: 「数式はプレビューを下に用意して、普通の部分は
編集しやすいように mermaid みたいなイメージ」）。

CodeMirror では `Decoration.widget({ block: true, side: 1 })` をブロック末尾に置いて実現する。
ソース行にはコードブロックと同じ背景を当てて、編集できる領域だと分かるようにする。

> 幅0の追加ウィジェットには行番号・差分ガターの marker を出さないこと
> （`block.length === 0` で判定）。出すと同じ行番号が2回並ぶ。

### 2.9 frontmatter `SHOULD`

- Obsidian はプロパティパネルに置換してカーソル侵入を禁じるが、**我々は生表示のままにする**。
  YAML を直接編集できることの方が VS Code では自然なため。
- 装飾（背景色を変える等）のみ行う。

**この1点は意図的に Obsidian と異なる。** 変更したい場合は設定で切り替える `SHOULD`。

## 3. キー操作要件

### 3.1 Enter `MUST`

| 状況 | 期待 |
|---|---|
| リスト項目の行末 | 次行に同じマーカーを継続 |
| リスト項目の途中 | 分割し、後半の行にマーカーを付ける |
| 空のリスト項目 | **マーカーを削除して空行にする**（行は増やさない） |
| 番号リスト | 次の番号を自動採番 |
| 空の番号リスト | マーカーを削除 |
| 未チェック / チェック済み項目の行末 | **常に未チェック `- [ ] ` で新項目**を作る |
| 引用行の行末 | `> ` を継続 |
| 見出しの行末 | **プレフィックスを引き継がない**（素の空行） |

### 3.2 Backspace `MUST` — 記法解除をしない

行頭付近の Backspace は**素の1文字削除**にする。
見出し降格・リスト解除といったインテリジェント処理を**入れてはならない**。

**受け入れ基準**
- `- 項目1` の C2 で Backspace → `-項目1`
- `# 見出し` の C2 で Backspace → `#見出し`
- `> 引用` の C2 で Backspace → `>引用`
- `- [ ] タスク` の C6 で Backspace → `- [ ]タスク`

> これは既存 Preview / Raw モードの `markerBackspace`（記法解除）と**正反対**である。
> Live モード では既存の実装を流用しないこと。

### 3.3 Tab / Shift+Tab `MUST`

| 状況 | 期待 |
|---|---|
| リスト項目 | インデント / アウトデント（挿入文字は VS Code の `editor.insertSpaces` に従う） |
| 複数行選択 | 選択中の全行をインデント / アウトデント |
| コードブロック内 | **ただの文字挿入**（インデント操作にしない） |
| リスト以外 | VS Code 既定の挙動 |

### 3.4 Home / End `MUST`

| 行 | `Home` 1回目 | `Home` 2回目 | `End` |
|---|---|---|---|
| リスト・チェックボックス | 本文先頭（マーカーの後ろ） | 行の物理先頭 C0 | 行末 |
| 見出し・引用・その他 | 行の物理先頭 C0 | — | 行末 |

### 3.4.1 Notion 風のブロック変換 `MUST`

`⌥⌘0`〜`⌥⌘9` で行のブロック種別を変える。対応表は Raw / Preview と共通の
`NOTION_BLOCK_KEYMAP` を使う（3モードで同じキーが同じ意味になるようにする）。

| キー | 種別 | キー | 種別 |
|---|---|---|---|
| ⌥⌘0 | 段落 | ⌥⌘5 | 箇条書き |
| ⌥⌘1 | 見出し1 | ⌥⌘6 | 番号リスト |
| ⌥⌘2 | 見出し2 | ⌥⌘8 | コードブロック |
| ⌥⌘3 | 見出し3 | ⌥⌘9 | 引用 |
| ⌥⌘4 | チェックボックス | | |

- 既存のプレフィックスは**必ず取り除いてから**新しいものを付ける（`## - 項目` のような
  壊れた行を作らない）。インデントは保つ。
- 複数行を選択しているときは選択が触れている全行に当てる。

### 3.4.2 スラッシュコマンド `MUST`

`/` を打つとコマンドメニューを出す。項目定義は Raw / Preview と共通の
`SLASH_MENU_ITEMS` を使う。行頭または空白の直後の `/` だけを拾い、
URL（`https://`）の中では発火しない。

### 3.5 自動ペア・囲み `SHOULD`

| 入力 | 選択なし | 選択あり |
|---|---|---|
| `[` | `[]` を挿入 | 選択を `[ ]` で囲む |
| `(` | `()` を挿入 | — |
| `*` | 自動ペア**しない** | 選択を `*　*` で囲む |
| `` ` `` / `"` | 自動ペア**しない** | — |

### 3.6 書式トグル `MUST`

| キー | 動作 |
|---|---|
| `⌘B` / `Ctrl+B` | 選択を `**…**` で囲む。既に太字の中なら**解除**。選択範囲は本文のまま維持 |
| `⌘I` / `Ctrl+I` | `*…*` で同様 |

### 3.7 Undo `MUST`

連続入力は1グループにまとめる。`Enter` によるマーカー自動挿入も1ステップで戻ること。

### 3.8 記法の入力変換 `MUST` — 変換処理を持たない

`# ` と打ったら**その瞬間からソースが `# ` である**ため、変換処理は不要。
「入力を検知して別のテキストに書き換える」処理を**入れてはならない**
（例: `[] ` を `[ ] ` に補正しない）。

例外的に許容する自動挿入は §2.6 の閉じフェンス補完のみ。

## 4. VS Code 統合要件

### 4.1 モードの提供 `MUST`

| 項目 | 値 |
|---|---|
| viewType | `ipreview.live` |
| コマンド | `markdownInline.openLive` (`Live`) |
| コマンド | `markdownInline.toggleLive`（Raw ⇄ Live モード） |
| 設定名前空間 | `markdownInline.live.*` |

**受け入れ基準**
- 既存の `ipreview.preview` を既定エディタにしている状態でも、Live モード を明示的に開ける。
- Live モード で開いても**タブが増殖しない**（既存 Preview と同じタブ管理規約に従う）。

### 4.2 ドキュメント同期 `MUST`

- webview 側の編集は VS Code の `TextDocument` へ**差分（range + text）で**反映する。
  文書全体の置き換えを**してはならない**（Undo 履歴と Git 差分が壊れるため）。
- 外部（Raw モード・AI・Git 操作）からの変更は webview へ差分適用する。
- ダーティ状態・保存・Undo/Redo は VS Code 側と一貫すること。

### 4.3 行番号ガター `SHOULD`

- 設定 `markdownInline.live.showLineNumbers`（既定 true）。
- **視覚行に1対1**で対応させ、ウィジェットに畳まれたブロックはその先頭ソース行番号のみ表示する
  （中間行の番号は表示しない）。

> CodeMirror 標準の `lineNumbers()` はブロックウィジェットに marker を付けないため、
> 畳まれたブロックの番号が丸ごと消える。`widgetMarker` を持つ独自ガター
> （`src/live/webview/liveLineNumbers.ts`）を使うこと。

### 4.4 Git 差分ガター `SHOULD`

- 設定 `markdownInline.live.showDiffGutter`（既定 true）。
- host が `git show HEAD:<file>` で取得した本文を `diffBase` メッセージで送り、
  webview 側で**行単位**の差分を取って左ガターに縦バーを出す。
- 配色は VS Code / GitHub に合わせる: **追加 = 緑 / 変更 = 青 / 削除 = 赤い三角**（削除位置の境界）。
- 保存のたびに HEAD 版を取り直す（コミット直後に差分が残らないように）。
- 記法の展開/収縮は**ドキュメントを変更しない**ので、差分ガターが誤って
  「変更あり」にならないこと（既存 Preview で発生した不具合 `63d6074` の再発防止）。

> CodeMirror のガターは「文書変更・ビューポート変更」でしか marker を計算し直さない。
> HEAD 本文は後から届くので、`lineMarkerChange` を指定しないと差分バーが一切出ない。
> また**マーカーが付いた行にしかガター要素は作られない**ため、
> どの行の差分かは marker の `data-line` で判別する。

### 4.5 コピー / ペースト `MUST`

- 選択範囲のコピーは**生 Markdown をそのまま**クリップボードへ載せる。
- 表・コールアウト等がレンダリングされていても、コピー結果はソースと完全一致すること。

### 4.6 IME `MUST`

- 日本語 IME の変換中（composition 中）は**展開/収縮の再計算を行わない**。
  確定後に1回だけ再計算する。
- 変換中にカーソルが飛ばないこと。

### 4.6.1 ツールバー `SHOULD`

画面上部に固定のツールバーを出す（設定 `markdownInline.live.showToolbar`、既定 true）。

- 左: ブロック変換（H1/H2/H3・チェックボックス・箇条書き・番号リスト・引用）と
  インライン書式（太字・斜体・インラインコード）
- 右: 現在のモード表示（Live）、**PDF 書き出し**、**Preview / Raw への切り替えボタン**
- PDF 書き出しは既存 Preview と同じ `exportToPdfLocal`（Chrome ヘッドレスの `--print-to-pdf`）を使う。
  コマンドパレットからも `Markdown Inline Preview: Export to PDF` で実行できる
- ボタンを押しても**エディタのフォーカスと選択を失わない**こと（`mousedown` で `preventDefault`）

### 4.7 背景・配色 `MUST`

**編集エリアの背景は VS Code / Cursor のテーマに関係なく常に白（紙）にする。**
（ユーザー指示 2026-08-05: 「そこの md ファイルの背景だけ常に白になるようにして欲しい」）

- ダークテーマのエディタの中で、この編集エリアだけが白い紙のように見えるのが意図した挙動。
- したがって `--vscode-*` 変数には依存せず、`media/live-preview.css` の固定パレットを使う。
- 本文・リンク・コード・引用などの色も、白背景で読めるものに固定する。

**受け入れ基準**: ダークテーマの実エディタで `.cm-editor` の背景が `rgb(255,255,255)` であること。

### 4.8 組版 `MUST`

ユーザー報告（2026-08-05）「引用が見えていない／全体的に見た目がチープ」への対応。
主観に流れないよう、**数値で押さえられるものはテストで固定する**
（`test/browser/live/rendering/typography.test.ts`）。

| 項目 | 要件 |
|---|---|
| フォント | 本文は**プロポーショナルのサンセリフ**（等幅にすると日本語が間延びする）。等幅はコード・数式・frontmatter だけ。総称ファミリ（sans-serif / monospace）はリストの**最後**にしか置けない点に注意 |
| 行間 | 本文の line-height は 1.5 以上（実装は 1.6） |
| 読み幅 | 上限 800px 以下で**中央寄せ**（実装は 800px）。画面が狭いときは画面幅に合わせて縮み、横スクロールを出さない。`.cm-content` は CodeMirror の基底テーマが `margin: 0` を当てるため、`.cm-editor .cm-content` と特異度を上げないと中央寄せが効かない |
| 装飾量 | 引用・コールアウト・コードの囲みは控えめに。背景はごく薄く、枠線は左罫線中心 |
| 本文の可読性 | 背景とのコントラスト比 7 以上 |
| 見出し | 上に 8px 以上の余白。H1/H2 は下罫線でブロックを区切る |
| 引用 | 左罫線は 3px 以上・背景とのコントラスト比 3 以上。本文の色は薄くしない（コントラスト比 4.5 以上）。背景色を敷いて塊に見せる |
| 箇条書き | 点は直径 4px 以上・背景とのコントラスト比 3 以上 |
| リストの揃え | 箇条書きとチェックボックスで**本文の開始位置が 4px 以内で揃う**（マーカーの表示幅を固定して揃える） |
| コードブロック | 等幅フォント・背景・枠・角丸 |
| 表 | セルのパディングは縦 5px 横 8px 以上。セル内のインライン記法は**装飾して表示**し、フォーカスしたセルだけ生の Markdown に戻す。CodeMirror の `word-break: break-word` が効いて語の途中で折り返すので、表の中だけ通常の改行規則へ戻す |

## 5. 非機能要件

| 項目 | 要件 |
|---|---|
| 起動 | 1万行のファイルを開いて操作可能になるまで 1 秒以内 `SHOULD` |
| 入力遅延 | キー入力から描画まで 16ms 以内（1フレーム）`SHOULD` |
| 大きなファイル | 画面外の行は装飾を計算しない（ビューポート単位で decoration を構築）`MUST` |
| エラー | webview 内の例外でエディタが操作不能にならないこと `MUST` |

## 6. 受け入れテスト計画

プロジェクトの掟（[docs/testing/testing-rules.md](../../testing/testing-rules.md)）に従い、
**実装より先にテストを書く**。レイヤー配分の方針:

| 検証したいこと | レイヤー | 置き場所 |
|---|---|---|
| 展開スコープの判定式（トークン境界・行・ブロック） | 純関数 | `test/suite/live/<category>/` |
| 実キー入力での Enter / Backspace / Tab の結果 | 実 Chromium | `test/browser/live/<category>/` |
| カーソル座標・クリック位置マッピング・展開時の横ずれ | 実 Chromium | `test/browser/live/cursor-focus/` |
| タブ管理・モード切替・設定連携・外部同期 | 実 VS Code | `test/extension/live/<category>/` |
| IME composition | 実 Chromium | `test/browser/live/ime/` |

カテゴリ語彙は既存（`cursor-focus` / `focus-expand` / `shortcuts` / `editing-core` /
`lists-tables` / `external-sync` / `rendering` / `ime` / `usage-flows`）をそのまま使う。

**必須の回帰テスト（最低限これが通らないとリリース不可）**

1. 任意のサンプル md を開いて閉じるとファイルがバイト単位で不変
2. トークン境界 `[from, to]` の展開判定（`**太字**` で 4〜14 のみ展開）
3. blur で全収縮、フォーカスで復帰
4. 行頭 Backspace が**記法解除しない**（4パターン）
5. 空リスト項目で Enter するとマーカーだけ消える
6. チェック済み項目の Enter で新項目が未チェックになる
7. 収縮中の文字をクリックしたときのカーソル着地位置
8. 全選択コピーの内容がソースと完全一致
9. 記法の展開だけでは Git 差分ガターが変更扱いにならない
10. リスト行で `Home` `Home` が C2 → C0
