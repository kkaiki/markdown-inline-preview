# テーブルインライン折り返し表示仕様書

## 概要

Markdown テーブルを、Preview ペインを開かずに、エディタ上で「改行されているように見える」形で表示するための仕様。

本機能は表示専用であり、元の Markdown テキストは原則として変更しない。

狙いは以下の 2 点。

- 横に長いテーブルでも、エディタ幅に収まる形で内容を把握しやすくする
- 既存の Markdown テーブル記法と整形機能を壊さずに、見た目だけを読みやすくする

---

## 背景

現在の Markdown テーブルは 1 行 1 レコードで表現されるため、列数やセル内容が増えると横方向に長くなりやすい。

その結果、以下の問題が起きる。

- エディタ上で右に大きくはみ出す
- Preview を開かないと全体像を掴みにくい
- 日本語を含む場合、見た目の幅と文字数が一致しにくい

本機能では、Markdown の生テキストはそのままに、インライン装飾で折り返し表示を行う。

---

## 用語

- 元テキスト:
  Markdown ファイルに保存されている実際の 1 行のテーブル記法

- 表示行:
  インライン装飾により、エディタ上で追加表示される見た目上の行

- 折り返し単位:
  1 行のテーブルを複数の表示行に分割する際の 1 まとまり

- 利用可能幅:
  エディタ上でテーブル表示に使ってよい横幅

---

## 対象

### 対象に含むもの

- Markdown テーブルのヘッダ行
- セパレータ行
- データ行
- 日本語を含むセル
- 表示専用の折り返し

### 対象に含まないもの

- 元テキストそのものを複数行化する自動変換
- CSV 風の別記法への変換
- Markdown 仕様外の表現の恒久保存
- 編集中のセルに対する強制的な整形

---

## 期待する体験

### 基本方針

- テーブルの元テキストは保持する
- 編集していない行では、折り返された表として読める見た目を優先する
- 編集中の行では、元テキストの編集しやすさを優先する

### 体験イメージ

元テキスト:

```md
| Name | Description | Notes |
| ---- | ----------- | ----- |
| Apple | A very long description that does not fit in the editor width | seasonal |
```

表示イメージ:

```text
| Name  | Description                        |
|       | Notes                              |
| ----- | ---------------------------------- |
|       | -----                              |
| Apple | A very long description that does  |
|       | not fit in the editor width        |
|       | seasonal                           |
```

上記は概念例であり、実際の分割位置は利用可能幅と各列幅に依存する。

---

## 機能要件

### 1. 折り返し表示の有効条件

- 対象ファイルが Markdown であること
- `markdownInline.enablePreview` が有効であること
- 新設する表表示設定が有効であること
- 対象行が Markdown テーブルブロックに含まれること
- 現在編集中の行ではないこと

### 2. 幅の取得

利用可能幅は、以下の情報から決定する。

1. 現在のエディタにおける表示幅を基準にする
2. 行番号、ガター、折りたたみ記号などの非本文領域は除外する
3. 文字幅計算は既存の table width calculation 設定に従う
4. 日本語や全角文字は既存ルールに従って幅を見積もる

実装上、VS Code API だけで厳密なピクセル幅が取れない場合は、以下の近似を許容する。

- エディタの visible range と文字幅ヒューリスティックを使った推定
- 設定値による最大表示幅の明示指定

### 3. 折り返しルール

- テーブル 1 行を、複数の表示行へ分割できる
- 分割は「列境界を保ったまま」行う
- 可能な限り左側の列を優先して残し、右側の列を下段へ送る
- 各表示行は、利用可能幅を超えないことを目標とする
- セパレータ行も、対応する列構成で同様に分割表示する

### 4. 列幅の決定

- 基本の列幅は既存のテーブル幅計算ロジックを使う
- ただし表示時は、エディタ幅に収めるため列幅の上限を設けられる
- 長すぎるセル内容は、列幅を無制限に拡張せず、セル内折り返しを優先する
- 最小列幅は可読性を壊さない範囲で持つ

### 5. セル内折り返し

- 1 つのセル内容が列幅を超える場合、セル内でも折り返して表示できる
- 折り返し位置は、空白、句読点、ハイフンなど自然な区切りを優先する
- 適切な区切りがない場合は文字単位で分割する
- 全角文字は途中で欠けて見えないように扱う

### 6. 編集時の振る舞い

- カーソルがある行は折り返し表示を外す
- その行は元テキストをそのまま見せる
- カーソルが別行へ移動した時点で再び折り返し表示対象に戻す
- IME 変換中は表示更新を抑制し、入力の邪魔をしない

### 6.1 表内の上下カーソル移動

- 折り返し表示を有効にしていても、表内の上下カーソル移動は既存のテーブルナビゲーション仕様を維持する
- `↑` と `↓` は、見た目上の折り返し行ではなく、元テキスト上の同じ列、同じセルを基準に移動する
- 移動先のセルが短い場合は、そのセル内で到達可能な末尾位置に丸める
- 折り返し表示の都合で、上下移動先が別セルにずれたり、継続表示行に吸われたりしてはならない

### 6.2 空白保持の例外

- 通常は表示用整形のために余分な空白を詰めてよい
- ただし、Markdown の意味を持つ先頭空白は保持対象とする
- 特に、チェックボックス表現の先頭に現れる 1 つの `[ ]` 用空白は許容し、削除や圧縮の対象にしない
- 例:

```text
[ ] Task
```

- 上記の `[ ]` 内の空白は、見た目の調整処理や折り返し処理によって失われてはならない

### 7. スクロールと再計算

- 以下のタイミングで表示を再計算する
  - ドキュメント変更時
  - カーソル移動時
  - エディタ切り替え時
  - 表示領域の変化時
  - 設定変更時

- 再計算は全行即時実行ではなく、デバウンスしてよい

---

## 表示ルール

### 1. 元テキストとの関係

- 保存対象は元テキストのみ
- 折り返し表示は decoration による見た目の追加情報とする
- コピー、検索、置換、Git diff の対象は元テキストとする

### 2. 視認性

- 折り返し後も、どの表示行が同じ元行に属するか分かること
- 継続行では、先頭列を空欄または継続記号で示してよい
- セパレータ行は、ヘッダの列構造が分かるように表示する

### 3. カーソル位置の整合性

- 折り返し表示上の見た目と、実際のカーソル位置が大きく乖離しないこと
- 操作対象は常に元テキストとする
- 見た目上の継続行を直接編集対象とはしない
- 上下移動時は、見た目上の行ではなく元の表セル座標を優先する

## 設定項目案

### 1. 有効化

- `markdownInline.table.inlineWrap.enabled`
  - 型: boolean
  - 既定値案: false
  - 説明: テーブルをインラインで折り返し表示する

### 2. 幅モード

- `markdownInline.table.inlineWrap.widthMode`
  - 型: string
  - 値: `editor`, `fixed`
  - 既定値案: `editor`
  - 説明:
    - `editor`: エディタ幅から自動計算
    - `fixed`: 固定カラム幅を使用

### 3. 固定幅

- `markdownInline.table.inlineWrap.maxWidth`
  - 型: number
  - 既定値案: 80
  - 説明: `fixed` モード時の最大表示幅

### 4. 最小列幅

- `markdownInline.table.inlineWrap.minColumnWidth`
  - 型: number
  - 既定値案: 8
  - 説明: 各列の最小表示幅

### 5. 継続行表示

- `markdownInline.table.inlineWrap.continuationStyle`
  - 型: string
  - 値: `blank`, `marker`
  - 既定値案: `blank`
  - 説明:
    - `blank`: 継続行の先頭を空表示にする
    - `marker`: 継続であることを示す記号を表示する

---

## 非機能要件

### 1. 非破壊性

- 元の Markdown テーブルを自動書き換えしない

### 2. 応答性

- 一般的なノートサイズでは、カーソル移動や入力時の体感遅延を最小にする

### 3. 互換性

- 既存の表整形機能と共存できること
- 既存のテーブルナビゲーション機能を壊さないこと

### 4. 日本語対応

- 全角文字を含む列でも見た目のズレを最小化する

---

## 制約

### 1. VS Code API 由来の制約

- エディタ本文の厳密なピクセル幅は取得しにくい
- decoration は本物の改行ではないため、見た目と編集対象が完全一致しない
- 行の高さや折り返し後のレイアウトに制約がある

### 2. そのため許容すること

- 幅計算は近似になる場合がある
- 一部テーマやフォントでは完全一致しない場合がある
- 長大テーブルは簡略表示や部分更新を行ってよい

---

## 想定エッジケース

- 罫線だけの不正な表
- セル数が行ごとに異なる表
- 1 セル内に非常に長い URL を含む表
- 日本語と英数字が混在する表
- 空セルが多い表
- カーソル行の前後だけ表示が切り替わるケース
- スクロールで可視範囲外に出た大きな表

---

## 受け入れ条件

### 最低条件

- 横に長い Markdown テーブルが、Preview ペインなしでも読める
- 元テキストは変更されない
- 編集中の行は通常表示に戻る
- 日本語を含む表でも大きく崩れない

### 品質条件

- エディタ幅変更時に表示が追従する
- 既存の表整形と競合しない
- カーソル移動時にちらつきや大きな遅延が出にくい

---

## 保留事項

以下は実装前に決めたい点。

1. 折り返しの主対象は「列を下段へ送る」方式か、「セル内を折り返す」方式か、または両対応か
2. 継続行で左側の見出し列を繰り返すか、空欄にするか
3. セパレータ行を毎回表示するか、先頭ブロックだけにするか
4. 幅取得を完全自動優先にするか、設定ベース優先にするか
5. 見た目上の折り返しを可視範囲だけに限定するか

現時点の第一案は以下。

- 基本は「列を下段へ送る」よりも「セル内折り返し」を優先する
- ただし列数が極端に多い場合のみ、列単位の段分けも許容する
- 幅は `editor` 自動推定を基本にし、必要なら `fixed` を逃げ道として持つ
