# 画像インラインプレビュー仕様書

## 概要

Markdown Inline Preview 上で、Markdown 画像記法をエディタ内で視覚的に確認できるようにするための仕様。

本仕様は 2 段階で定義する。

- フェーズ 1: 通常の画像プレビュー
- フェーズ 2: 画像の上に別画像を重ねるオーバーレイ表示

目的は、Preview ペインを別に開かなくても、Markdown 編集中に画像の存在と見た目を把握しやすくすること。

---

## 背景

現在の拡張機能は、チェックボックス、見出し、コードブロック、横線などを `TextEditorDecorationType` で視覚化しているが、画像記法は未対応である。

そのため、以下の課題がある。

- `![alt](path)` を書いても、エディタ上ではパス文字列しか見えない
- 画像の実体確認には Markdown Preview か外部ビューアが必要
- 画像の上に別画像を重ねるような表現は、標準 Markdown だけでは表せない

---

## 結論

### 1. 通常画像のプレビュー

実現可能。

- 非編集中の画像行に対して、エディタ decoration または hover を使った画像プレビューを提供する
- 元の Markdown テキストは保持する

### 2. 画像の上に画像を重ねる表現

標準 Markdown だけでは不可能。

- `![base](...)` だけでは、位置指定付きオーバーレイの意味を持てない
- 実現するには、拡張独自構文または HTML ベースの拡張表現を導入する必要がある
- 表示方式は editor decoration だけで完結させず、hover または webview を併用する前提とする

---

## 用語

- 画像行:
  `![alt](path)` を含む Markdown の行

- ベース画像:
  背景として表示する画像

- オーバーレイ画像:
  ベース画像の上に重ねる補助画像

- 非編集中:
  カーソルがその行にない状態

---

## 対象

### 対象に含むもの

- Markdown 画像記法 `![alt](path)`
- ワークスペース内の相対パス画像
- `http://` `https://` の絶対 URL 画像
- 非編集中行での視覚プレビュー
- 将来的なオーバーレイ画像表示

### 対象に含まないもの

- 画像編集機能
- ドラッグでの自由配置 UI
- Photoshop のようなレイヤー編集
- PDF や動画の埋め込みプレビュー

---

## 設計原則

### 1. 非破壊

- 元の Markdown テキストは保持する
- プレビューは表示専用とする

### 2. 編集優先

- 編集中の行では生の Markdown を見せる
- カーソルが外れたらプレビューを再適用する

### 3. 段階導入

- まず通常画像の視認性改善を実装する
- オーバーレイは別フェーズで導入する

### 4. API 制約を前提にする

- VS Code の editor decoration は完全な WYSIWYG キャンバスではない
- 複雑な重ね描画は hover または webview を補助的に使う

---

## フェーズ 1: 通常画像プレビュー

## 対象構文

```md
![alt text](./images/sample.png)
![remote](https://example.com/image.png)
```

## 期待する体験

- 非編集中の画像行では、画像のパス文字列だけでなくサムネイル相当の見た目を確認できる
- 編集中は生テキストへ戻る
- 画像が読めない場合は壊れたプレビューではなくエラー表示へフォールバックする

## 機能要件

### 1. 有効条件

- 対象ファイルが Markdown であること
- `markdownInline.enablePreview` が有効であること
- 新設する画像プレビュー設定が有効であること
- 対象行が画像記法として解釈できること
- 現在編集中の行ではないこと

### 2. 画像ソース解決

- 相対パスはドキュメント基準で解決する
- 絶対 URL はそのまま扱う
- 画像読込に失敗した場合は alt とパスを残したまま、失敗状態を表示する

### 3. 表示方式

MVP では次の優先順位で対応する。

1. 行内または行末に小さなサムネイルを表示
2. hover 時に大きめの画像プレビューを表示
3. API 制約で 1 が難しい場合でも、少なくとも 2 は提供する

### 4. 編集時の振る舞い

- カーソルがある行では画像 decoration を外す
- 行を離れたら再描画する
- IME 変換中は過剰な更新を抑制する

### 5. エラー表示

- ファイルが存在しない
- 非対応拡張子
- 読込権限なし
- URL の取得失敗

上記では、画像表示の代わりに簡潔なプレースホルダを出す。

例:

```text
[image preview unavailable]
```

## フェーズ 2: オーバーレイ画像表示

## 前提

標準 Markdown の画像構文は、1 枚の画像参照しか表現できない。

そのため、画像の上に別画像を重ねる機能は、拡張独自構文を導入して扱う。

## 構文案

### 案 A: 属性付き単一行構文

```md
![base](./base.png){overlay=./stamp.png,x=24,y=16,width=80,height=80,opacity=0.9}
```

利点:

- 1 行で完結する
- 通常画像構文から拡張しやすい

欠点:

- Markdown 標準ではない
- 属性パースが複雑になりやすい

### 案 B: ディレクティブ構文

```md
:::markdown-inline-image
base: ./base.png
overlay: ./stamp.png
x: 24
y: 16
width: 80
height: 80
opacity: 0.9
alt: sample composite
:::
```

利点:

- 可読性が高い
- 将来の拡張が容易

欠点:

- 行数を使う
- プレーン Markdown としては可搬性が低い

本仕様では、将来拡張性を優先して案 B を推奨する。

## オーバーレイ要件

### 1. ベース画像

- 必須
- 画像全体の基準座標となる

### 2. オーバーレイ画像

- 1 枚以上を将来拡張対象とする
- 初期実装は 1 枚までに限定してよい

### 3. 配置情報

- `x`: 左上基準の X 座標
- `y`: 左上基準の Y 座標
- `width`: オーバーレイ表示幅
- `height`: オーバーレイ表示高
- `opacity`: 0.0 から 1.0

### 4. 表示方式

- editor decoration だけで正確な重ね描画が難しい場合、hover または webview で合成結果を表示する
- 非編集中行では「合成プレビューあり」の視覚マーカーを出す
- クリックまたは hover で合成画像の詳細を確認できるようにする

### 5. 編集時の振る舞い

- 構文ブロック編集中は生テキストを表示する
- ブロック外ではプレビューを表示する

---

## UI 仕様

## 基本表示

- 非編集中行:
  画像サムネイルまたは合成プレビューを表示

- 編集中行:
  生の Markdown 構文を表示

- エラー時:
  画像未読込プレースホルダを表示

## 推奨 UX

- 行全体を画像に置き換えない
- 元の画像構文が存在することは薄くでも認識できるようにする
- 高さの大きい画像は最大高さを超えたら縮小表示する

---

## 設定項目案

### 1. 通常画像プレビュー

- `markdownInline.imagePreview.enabled`
  - 型: boolean
  - 既定値案: false
  - 説明: Markdown 画像記法のインラインプレビューを有効化する

- `markdownInline.imagePreview.mode`
  - 型: string
  - 値: `inline`, `hover`, `inlineAndHover`
  - 既定値案: `inlineAndHover`
  - 説明: 画像プレビューの表示方式

- `markdownInline.imagePreview.maxWidth`
  - 型: number
  - 既定値案: 240
  - 説明: サムネイル最大幅

- `markdownInline.imagePreview.maxHeight`
  - 型: number
  - 既定値案: 160
  - 説明: サムネイル最大高さ

### 2. オーバーレイ画像

- `markdownInline.imageOverlay.enabled`
  - 型: boolean
  - 既定値案: false
  - 説明: 拡張構文による画像オーバーレイプレビューを有効化する

- `markdownInline.imageOverlay.syntax`
  - 型: string
  - 値: `directive`, `attribute`
  - 既定値案: `directive`
  - 説明: オーバーレイ画像構文の解釈方式

- `markdownInline.imageOverlay.previewMode`
  - 型: string
  - 値: `hover`, `webview`, `auto`
  - 既定値案: `auto`
  - 説明: 合成結果の表示方式

---

## 非機能要件

### 1. パフォーマンス

- 同一画像の再読込は避け、キャッシュを持つ
- 大量画像ファイルでは遅延読み込みを許容する
- スクロール領域外の画像は積極的に更新しなくてよい

### 2. 安全性

- 外部 URL 読込時は VS Code の制約とセキュリティ方針に従う
- HTML を使う表示はサニタイズ前提とする

### 3. 互換性

- 標準 Markdown と競合しないこと
- 独自構文は、未対応環境でも最低限テキストとして読めること

---

## 実装方針案

### ステップ 1

- 画像記法のパターン抽出を追加
- 相対パス解決を追加
- hover プレビューを先に実装

### ステップ 2

- 小さなインラインサムネイルを追加
- 編集行の除外、キャッシュ、エラー表示を追加

### ステップ 3

- オーバーレイ用の独自構文を追加
- hover または webview で合成表示を追加

### ステップ 4

- 必要なら editor 内サムネイルと合成プレビューの連携を改善

---

## 制限事項

- editor decoration のみでは自由な座標系レイヤー UI は難しい
- 元テキストと見た目の高さが完全一致しない可能性がある
- ネットワーク画像は環境によって読込可否が変わる
- 標準 Markdown だけでは画像オーバーレイを表現できない

---

## 受け入れ基準

### フェーズ 1

- `![alt](path)` を含む非編集中行で画像の存在が視覚的に分かる
- フォーカス時は元の Markdown 構文に戻る
- 無効パスでもエディタ操作が壊れない

### フェーズ 2

- 独自構文からベース画像とオーバーレイ画像を解釈できる
- 座標、サイズ、透明度が反映された合成プレビューを確認できる
- 構文エラー時は安全にフォールバックする
