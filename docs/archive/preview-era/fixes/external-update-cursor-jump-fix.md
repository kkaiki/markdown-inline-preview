# 外部 update でカーソルが飛び、入力が外部の行へ混入する不具合の修正 仕様

最終更新: 2026-07-02

## 1. 症状

Preview で編集中に外部（Raw エディタ・AI・他ツール）が同じファイルを編集し、
その反映（`{ type: 'update', markdown }` → `applyExternalContent`）が届くと:

- カーソルが編集中のブロックから**外部が編集/追加した行へ飛ぶ**
- 直後に続けてタイプした文字が**外部の行に混入する**
  （例: 外部が末尾に「外部が追加した行」を足した直後に「を買う」と打つと
  「外部が追加した行を買う」になる）

実 Chromium テスト `test/browser/externalUpdateRace.test.ts` で決定的に再現。
チェックボックス変換ガードの 1000ms 窓とは無関係に、update 単体で起きる。

## 2. 根本原因（2 段階で特定）

1. 旧実装は `replaceAll`（文書全置換）+「選択位置を**数値のまま**新文書サイズへ
   クランプ」だった。カーソルより前が 1 文字でも増減すると絶対位置がズレ、
   別のブロックの中へ着地する。
2. 差分置換（変わったブロックだけ置換）に変えても、ブロックの同一性を
   `node.eq`（attrs まで含む厳密比較）で判定すると不十分だった。
   **タイプ操作で作られたノードとパーサが作ったノードは、保存 Markdown が同一でも
   内部 attrs（リストの `spread` 等）が食い違う**ため「全部変わった」扱いになり、
   カーソルのいるブロックまで置換されてしまう。

## 3. 修正方針（`applyExternalContent.ts`）

1. 新しい Markdown を `parserCtx` でパースし、トップレベルブロック単位の
   共通プレフィックス／サフィックスを除いた「実際に変わった範囲」だけを
   1 トランザクションの `tr.replaceWith` で置換する。選択は ProseMirror の
   マッピングで自動追従するため、変更範囲の外のカーソルは同じブロック・同じ
   相対位置に残る（変更範囲の内側にいた場合のみ端へ寄る）。
2. ブロックの同一性判定は `node.eq` **または**「ブロック単体を Markdown へ
   シリアライズした文字列の一致」（`serializerCtx` + `schema.topNodeType.create`、
   行番号ガターの `serializeBlock` と同じ手法）。保存ファイル観点で同じブロックは
   置換しない。attrs の変化（例: 外部がチェックボックスを ✓ にした）は
   シリアライズ結果に現れるので取りこぼさない。
3. パースやスキーマ都合で差分置換に失敗した場合は、従来の
   「全置換 + 数値クランプ」へフォールバック（クラッシュより位置ズレを選ぶ）。

## 4. テスト

- `test/browser/externalUpdateRace.test.ts`（実 Chromium・4 件）:
  チェックボックス変換直後（ガード窓内）の update でカーソルが項目に残る、
  update 直後の続き入力が元の項目に入る、段落途中のカーソルが同じ段落に残る、
  文書が大幅に短くなる update でも落ちず入力を続けられる。
- `test/webview/applyExternalContent.integration.test.ts`（jsdom・既存 4 件）:
  置換の反映・クランプ・空文書置換の回帰防壁（新実装でもそのまま通る）。
