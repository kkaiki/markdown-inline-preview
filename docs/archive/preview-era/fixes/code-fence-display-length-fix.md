# 表示フェンスの長さがソースと一致しない不具合の修正（code-fence-display-length-fix）

最終更新: 2026-07-27

## 症状（ユーザー報告 2026-07-27）

内容自体が `` ``` `` を含むコードブロック（ネストフェンス）で、Preview の見た目が崩れる。
`` ``` `` の行が2行並び、どれが外側フェンスでどれが内容なのか分からない。

ソース（Raw）:

````text
````
```
Animate the attached image ...
```
````
````

これまでの Preview の表示:

```text
```        ← 表示用フェンス widget（常に3連固定）
```        ← 内容の1行目
Animate the attached image ...
```        ← 内容の最終行
```        ← 表示用フェンス widget（常に3連固定）
```

## 真因

`lineNumberGutterPlugin.ts` はコードブロックの開き/閉じフェンス行を widget
（`.code-fence-display`）として描画しているが、その文字列が `` ``` `` 固定だった。

保存 Markdown 側は remark-stringify（mdast-util-to-markdown）が
「内容に含まれる最長のバッククォート連 + 1、最低 3」でフェンスを広げる。つまり
ソースは `` ```` `` なのに、表示だけが `` ``` `` になっていた。

## 修正

直列化側と同じ規則で表示用フェンスを計算する純関数
`codeFenceMarker(content)`（`lineNumberGutterPlugin.ts`）を追加し、開き
（`marker + language`）・閉じ（`marker`）の両方で使う。

- 内容にバッククォート連が無い/2連まで → `` ``` ``（従来どおり）
- 内容に3連 → `` ```` ``
- 内容に4連 → `` ````` ``

## 追加修正: 閉じフェンスだけが選択ハイライトに入る（2026-07-27）

同じ表示用フェンス widget について、**コード本文を選択すると閉じフェンス行だけが青く
塗られ、開きフェンス行は塗られない**という非対称もあった（ユーザー報告のスクリーン
ショット）。

原因は widget decoration の `side` が全て `-1`（＝その位置の**手前**に描画）だったこと。
閉じフェンスの位置は「コード本文の終端」なので、本文全体を選択したときの DOM 上の
選択終端（`<code>` 要素の子オフセット）が widget の**後ろ**に来てしまい、
`getSelection().containsNode(閉じフェンス)` が true になっていた。開きフェンスは
選択開始位置の手前にあるため元から false。

閉じフェンスの widget だけ `side: 1`（位置の後ろ）にして、選択範囲の外に出した。
副次的に、コード本文の末尾へ置いたキャレットが widget の後ろの DOM 位置
（矩形が取れない ＝ ``` の下に空行があるように見える）へ回る問題も解消した。

**例外: mermaid ブロック**。図として描画されるブロックでこの widget を終端位置の後ろへ
動かすと、図内テキストのドラッグ選択が空になる（`mermaidTextSelection.test.ts` が検出）。
図の中には「コード本文の最終行」が見えておらず、フェンスが選択ハイライトに入る問題も
起きないため、mermaid ブロックだけ `side: -1` のままにしている。
表示位置は変わらない（同じ DOM 位置に描画される）。widget の再利用キーにも `side` を
含め、`side` 違いで古い DOM が使い回されないようにしている。
