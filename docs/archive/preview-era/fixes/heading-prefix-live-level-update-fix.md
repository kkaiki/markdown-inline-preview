# Preview: 見出しプレフィックス編集中に見た目のレベルをリアルタイム反映する 仕様

最終更新: 2026-07-09

## 1. 症状

見出し（例: `### 見出し`）にフォーカスすると `blockPrefixEditPlugin` が `### ` を実テキストとして
展開する。この状態で `#` を1つ Backspace で削除しても（`## 見出し` になっても）、フォーカスを
外す（collapse する）までは見出しの実レベル（`heading` ノードの `attrs.level`、見た目の
フォントサイズに対応）が更新されず、元のレベルのまま表示され続ける。ユーザーからは
「`#` を1つ消したら、その場でH2サイズになってほしい（フォーカスを外すまで待ちたくない）」
という要望（2026-07-09）。

## 2. 原因

見出しレベルの再計算は `collapseHeading`（フォーカスを外したときだけ呼ばれる）にしか
実装されていなかった。展開中（フォーカスがまだブロック内にある間）は、`appendTransaction`
が `expandedBlock.nodePos`/`contentStart` の位置追跡だけを行い、レベル自体の再計算は
していなかった。

## 3. 修正

`blockPrefixEditPlugin.ts` の `appendTransaction` に、位置追跡の直後、見出しブロックの
`docChanged`（自プラグインの `tr` を除く）を検知したら、`collapseHeading` と同じ正規表現
`/^(#{1,6})\s/` で現在の実テキストのプレフィックスを判定し、マッチした `#` の個数が
現在の `node.attrs.level` と異なれば `setNodeMarkup` でレベルを即座に更新するロジックを
追加した。

- `#` が1〜6個で、かつ区切り文字が続く（マッチする）場合のみレベルを更新する。
- マッチしない場合（`#` が0個、または7個以上で見出し記法として成立しない見た目）は
  何もしない。段落への変換は従来どおり `collapseHeading`（フォーカスを外したとき）の
  責務のまま変えない — 展開中に途中経過（例えば全部消している最中）で段落化してしまうと、
  ユーザーがまだ `#` を打ち直すつもりのときにノード種別が振動してしまうため。
- `setMeta(PLUGIN_META, 'liveLevel')` を付けて `markdownUpdated` リスナー等の既存の
  「展開中は抑制」ガードに影響しないようにする（`addToHistory: false` で undo 履歴も汚さない）。

## 4. テスト

`test/browser/focus-expand/headingPrefixBackspaceLevel.test.ts`:
- `"#"` を Backspace で削除した直後（フォーカスを外す前）に、見出しの実レベルが
  リアルタイムで更新される（`### ` → `## ` で `heading(2)` になることを、まだ本文へ
  フォーカスを移す前に確認）
